# Vite to Next.js / Create T3 App migration

## Status

In progress on `migration/nextjs-t3`.

The final Vite baseline is commit `e65f895`. The migration is intentionally
split so the new application lands before obsolete Vite entrypoints are
removed.

## Why migrate

The game already uses React, Three.js, TypeScript, Supabase, and Vercel. Moving
the application shell to Next.js App Router gives the public game and private
editor explicit routes, aligns the repository with a current Create T3 App
foundation, and removes the Vite-specific multi-page routing layer.

Create T3 App remains modular: the migration uses App Router, Tailwind CSS, and
ESLint without adding tRPC, an ORM, or a second authentication system. Supabase
continues to own level persistence and editor authentication.

## Scaffold

The sibling staging project was generated with:

```powershell
npm create t3-app@latest cube-game-next -- --CI --tailwind --appRouter --eslint --noGit
```

Its reviewed source was copied into this Git worktree while excluding:

- `node_modules/`
- `.next/`
- `.env` and `.env.local`
- `agent-files/`
- `*.tsbuildinfo`

The repository's existing `.git` worktree metadata was preserved.

## Route mapping

| Before | After | Notes |
| --- | --- | --- |
| Vite `/` through `index.html` | App Router `/` | Loads the Three.js game as a no-SSR client island. |
| Vite rewrite-backed `/editor` | App Router `/editor` | Real route with the existing private Supabase sign-in boundary. |
| Vite `/legacy` | Retired after migration acceptance | Recoverable from the Vite baseline commit/tag. |

## Architecture boundary

- `src/app/` owns App Router pages, metadata, viewport configuration, and the
  client-island boundary.
- `src/game/` owns the preserved React/Three.js game, deterministic engine,
  level model, Supabase client, and editor components.
- `src/voxel-art/` contains the voxel generator used by the game.
- `src/styles/globals.css` contains Tailwind plus the preserved game styling.
- The public game uses `next/dynamic` with `ssr: false` because WebGL,
  fullscreen handling, local storage, and tutorial initialization require
  browser APIs.

The deterministic engine and level model remain framework-independent
JavaScript during this migration. Converting those established modules to
TypeScript is deliberately outside the framework cutover.

## Environment variables

| Vite | Next.js |
| --- | --- |
| `VITE_SUPABASE_URL` | `NEXT_PUBLIC_SUPABASE_URL` |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` |

Only public Supabase project values are exposed to the browser. Local values
belong in ignored `.env.local`; `.env.example` contains empty placeholders.

## Verification

Required before merge:

```powershell
npm install
npm run check
npm run test:engine
npm run build
```

Focused browser acceptance:

- dismiss the first-run tutorial;
- orbit the World Cube with an empty-space drag;
- enter Interior mode;
- move the Ape one cell with an arrow key;
- open Settings;
- confirm `/editor` exposes only its sign-in boundary before authentication;
- confirm no new application errors appear in the browser or dev server.

The sibling staging project passed these checks on Next.js 16.2.11. They must
be repeated in this worktree after the Vite files are retired.

## Deployment cutover

1. Configure the two `NEXT_PUBLIC_SUPABASE_*` values in the deployment.
2. Deploy the migration branch as a preview.
3. Repeat the focused browser acceptance flow against the preview URL.
4. Merge only after `/` and `/editor` are accepted.
5. Verify the production deployment before removing the Vite rollback tag.

No Vite rewrites should remain in `vercel.json`; Next.js owns both routes.

## Rollback

The migration is Git-only and recoverable. If the production cutover fails,
redeploy the final Vite commit/tag or revert the migration PR. Do not mix
emergency gameplay changes into the rollback.
